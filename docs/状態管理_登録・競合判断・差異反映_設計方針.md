# 新ファイル基準表：状態管理の整理（設計方針・未実装）

更新日：2026-10-28
対象：BUD-147／frmSyncReview／3方向比較／差分CSV

> この文書は利用者との協議で合意した**設計方針**を記録する。現行VBAの実装仕様・検証済み挙動を保証するものではない。実装前に既存の「同期状態」列、Step2・Step4、3方向比較、CSV出力条件を調査すること。

## 背景

既存ファイルの分類名1・分類コード1について、文書管理システム側「土木／2」、Excel側「工務／3」の競合でExcel側を採用した。Excel側の値は維持され、文書管理システムへの反映は未実施にもかかわらず、基準表の「同期状態」は「同期済」と表示された。

「同期済」はファイルの登録・照合が済んでいることと、両側の値が一致し反映が完了したことを混同させやすい。既存の「登録予定」を流用すると、新規ファイルとして扱われる可能性があるため、現行コードを確認せず変更しない。

## 合意した概念上の区分

| 軸 | 例 | 意味 |
| --- | --- | --- |
| 登録・紐付け状態 | 新規登録待ち／登録済み | 文書管理システムに対象ファイルが存在し、ファイルID等で対応付けられているか |
| 競合判断状態 | 未判断／Excel採用／システム採用／保留 | 競合する値についてどちらを正とするか判断済みか |
| 差異反映状態 | 反映不要／システム反映待ち／Excel反映待ち／要確認 | 判断結果や3方向比較に基づき、どちらへの変更反映が残っているか |

※名称は概念上の仮称。「登録予定」「同期済」の現行列を置換する決定ではない。新しい列の追加も未決定。

### 具体例

- 既存ファイルID 228485、R8「吉田建材㈱生コン工場」
- システム側：分類名1「土木」、分類コード1「2」
- Excel側：分類名1「工務」、分類コード1「3」
- Excel側を採用する判断は実施済み、システムへの更新は未実施
- **概念上**：登録済み／Excel採用済み／**システム反映待ち**
- この状態を「新規登録待ち」や「両側一致済み」と扱わない。

## 実装前の必須確認

1. 既存「同期状態」（登録予定／同期済等）の実際の意味、更新条件、Step2取り込み時の変換条件。
2. 登録予定が新規登録・ファイル照合・ファイルIDに及ぼす影響。
3. 3方向比較での「Excelのみ変更」「システムのみ変更」「両方変更」「両方一致」の扱いと、競合判断履歴の保存先。
4. Step4差分CSVに何が出力され、何をもって「システム反映完了」と確認できるか。**CSVを作成しただけで反映完了としない**。
5. 内部管理項目の未判断がStep4出力を止める現行ゲートとの整合性（BUD-147残課題）。
6. 状態の表示場所・保持方法（既存列維持＋別表示／新規列など）と再同期時の遷移。

## 原則

- 新規ファイル追加と既存ファイル更新を区別する。
- 登録・紐付け状態と差異反映状態を混同しない。
- 「システム反映待ち」はExcelを正と判断したがシステムへの適用が未確認の状態を指す。
- 「Excel反映待ち」はシステム側を正としExcelへの適用が未確認の状態を指す。
- 実際に相手側へ反映されたことを確認してから反映完了に遷移させる。
- ファイルID・管理行ID・連動コード・判断履歴を保護する。
- **本書だけを根拠にVBA、Excel列、Step2・Step4を変更しない。** 実装仕様を確定し、別途検証する。
