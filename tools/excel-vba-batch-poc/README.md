# Excel VBA 非対話 PoC（ダミー専用）

実際の業務ブック向けのツールではなく、使い捨ての空ブックを作成して `Workbook_Open` を実証する最小例です。業務データ・既存ブック・CSV・既存VBAには使用しないでください。未確認のコードを `ThisWorkbook.bas` に入れて実行しないでください。

## 環境と使い方

WindowsのMicrosoft Excel、Python、pywin32、openpyxlが必要です。ExcelのVBAプロジェクトへのアクセスが既に許可されている必要があります。設定変更やポリシーの迂回は行いません。このPCではExcel 16.0、Python 3.14.7、pywin32 312、openpyxl 3.1.5で確認しました。

1. `poc.py` と `ThisWorkbook.bas` の2ファイルを、リポジトリ外の**新規の空フォルダ**へコピーします。既存ファイルを上書きしないでください。
2. そのフォルダで `python poc.py` を実行します。1フォルダ1回限りです。再実行する場合は別の空フォルダを使い、前回の記録を保持してください。
3. `run.json`、`worker.jsonl`、`vba-result.txt`、`dummy.xlsm` を確認します。`run.json` の `attempt` は**そのフォルダ内**の回数で、作業全体の累積試行数ではありません。累積台帳は別途必要です。

## 動作と安全境界

- 監督Pythonが実行IDを作り、別WorkerからExcelを `DispatchEx` で起動します。既存PIDと一致する場合は変更せず停止します。Excelの起動情報と所有者を記録し、既にブックがある場合は終了操作を送らず停止します。
- 新規 `dummy.xlsm` のA1は空、A2は `R8`、A3は実行IDです。`ThisWorkbook` に検証VBAを入れて保存し、再度開くと `Workbook_Open` がA2を読み、A1に `R8・処理完了` を書き保存し、結果ファイルを作成します。画面入力・InputBox・UserFormは使いません。
- Excel終了後、保存されたブックをopenpyxlで読み、実行ID付きVBA結果、A1〜A3、プロセスハンドルの終了確認、PID不在、Workerの状態を合わせて判定します。COMの戻り値だけでは合格としません。
- Excel全体の設定・レジストリは変更しません。ただし今回起動した自動化インスタンスの `AutomationSecurity` は実測で `1` でした。自動化時には開くブックのマクロが実行され得ます。検証対象以外は開かないでください。`DisplayAlerts=False` はこの専用インスタンスだけです。
- 90秒で監督側がWorkerを終了します。Excel全体の強制終了は行いません。Excelは残ることがあり、その場合はPID・起動時刻・所有者・対象ブックを確認し、確実に特定できない限り終了しないでください。想定外ウィンドウの観測は0.25秒間隔であり、無表示の完全保証ではありません。
- `PASS` は上記事後条件のすべてが成立した場合だけです。VBAエラーや期待値不一致は `FAIL`、証拠不足・タイムアウト等は `INCONCLUSIVE` です。ログの `approval_request` はこのダミーに承認処理がないという意味で、実業務の承認を代行・省略するものではありません。

## 実機結果と未検証

2026-11-11のノートPC実行では、正常系でA1が期待値になり、結果ファイルと保存後読取り、Excelプロセス終了を確認しました。別のダミー試行では意図的なVBAエラー513を結果ファイルに記録し、A1が空のまま終了して `FAIL` と判定しました。最終コードはその後、予期しない起動ブックを保護するガードとopenpyxlの読取り処理を修正し、正常系を再確認しています。エラー試行時のコードとの差はその2点です。

実Excelが応答しないタイムアウト、予期しない起動ブック、実承認、業務用マクロ・CSV・フォームは未検証です。画面表示が必要な業務処理を自動化できるとは証明していません。BUD-151への応用は別設計・別検証が必要です。
