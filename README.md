# file-index-sync

## 利用者向け運用取扱説明書

実務での追加・更新・削除、Excel側と管理システム側の使い分け、座作成、仮採番、黄色表示、同期状態などは、**[新ファイル基準表・管理システム 運用取扱説明書](./新ファイル基準表.md)** を正本として確認してください。

利用者の操作方法・判定・状態・処理順に影響するコード変更を行う場合は、**コード変更と同時に `新ファイル基準表.md` も更新する**ことを運用ルールとします。

## プロジェクト概要
`新ファイル基準表.xlsx` を中心に、CSV 整形・コードマスタ補完・差分インポート CSV 生成までを一貫して管理するためのリポジトリです。

## 目的
- ローカル作業フォルダの成果物（Excel ブック、マクロ、CSV、ドキュメント）を Git/GitHub で履歴管理する
- 定型作業の手順を明文化し、再現性を上げる
- 差分インポートに必要な CSV を安定して作成できる状態を保つ

## 想定フロー
1. CSV 出力
2. `手順1_目録CSVを取り込む` で CSV を選択し、`目録CSV` シートへ上書き取込
3. `手順2_新ファイル基準表を作成する` で `新ファイル基準表` を生成
4. `手順3_コード管理CSVを作成する` で `コード管理CSV` のコード/表示名マスタを抽出
5. `コード管理CSV` を参照してコード補完
6. `手順4_差分インポートCSVを作成する` で更新行と新規追加行を抽出
7. 差分インポート CSV 生成

## シートの役割
- `目録CSV`: 元CSV保持用（取込のみ。整形しない）
- `目録CSV` の想定構造:
  1行目=見出し、2行目以降=データ
- `新ファイル基準表`: 表示用の整形結果シート（`目録CSV` の全列をコピー後、指定列を左から順に並べ替えて表示。指定外列は削除せず非表示で保持）
  - ファイルID
  - ファイル番号
  - バーコード番号
  - 毎年度利用区分1:毎年作成 2:単年のみ
  - 原課
  - 年度（和暦）
  - 分類名１
  - 分類名２
  - 分類名３
  - タイトル
  - 保存期間
  - 媒体種別
- `コード管理CSV`: コード対応管理
  - `目録CSV` から抽出した「区分 / 表示名 / コード」の対応マスタを保持
- `差分インポートCSV`: インポート用出力

## 利用者向けマクロ
- `一括_取込から新ファイル基準表作成まで`: 通常運用で使う推奨マクロ（CSV取込 → 新ファイル基準表作成）
- `手順1_目録CSVを取り込む`: CSV ファイルを選択し、Shift-JIS(932) 前提で `目録CSV` シートへ上書き取込
  - 取込直後に見出し行（1行目）の改行コード（vbCrLf / vbCr / vbLf）を除去して見出し一致を安定化
- `手順2_新ファイル基準表を作成する`: `目録CSV` の全列コピー後、指定12列を左側に並べ替え。キー列（ファイルID/ファイル番号/バーコード番号）は列を保持したまま非表示にし、編集対象列のみ表示（存在しない見出しはスキップ。他列は非表示、削除しない）。「毎年度利用区分1:毎年作成 2:単年のみ」は 1→毎年作成、2→単年のみ に表示変換。CSV 整形は現状同期のため、年度繰上げやタイトル内年度変換は行わない。整形開始時に対象年度の「通し番号」列の塗りつぶしをクリアし、今回新規追加された行または既存行から内容変更があった行のみ「通し番号」セルを赤色で塗りつぶす。新ファイル基準表の既存列幅は自動調整せず、利用者が手動調整した幅を維持する
- `手順3_コード管理CSVを作成する`: `目録CSV` からコード⇔表示名を抽出（項目名/コード/表示名）し、固定選択肢マスタ（毎年度利用区分、年度暦年区分、完結区分、公開区分、歴史資料区分、廃棄区分、履歴ファイル区分、機密ファイル区分）も重複除外して `コード管理CSV` に出力
- `手順4_差分インポートCSVを作成する`: `目録CSV` と `新ファイル基準表` をキー（ファイルID/ファイル番号/バーコード番号）で比較し、更新行と条件一致する新規追加行のみを固定見出しレイアウトで `差分インポートCSV` へ出力（同名見出しがない列は空白。`所管所属` は `原課ID`、`毎年度利用区分` は `毎年度利用区分1:毎年作成 2:単年のみ` から取得）
- `nプラス1_毎年作成年度補正を実行する`: CSV 整形とは別に、毎年作成行のタイトル年度表現を n+1 用に補正する分離マクロ
- 通常は「1. CSV取込 → 2. 新ファイル基準表作成」の順で使用

## 新ファイル基準表のID自動補完（Worksheet_Change）設定
- `新ファイル基準表` で表示名入力時にID列へ自動補完するには、**シートモジュール**に `Worksheet_Change` が必要です。
- 貼り付け先: `VBAProject > Microsoft Excel Objects > 新ファイル基準表`
- コードは `新ファイル基準表_SheetModule.bas` を使用してください（標準モジュールでは発火しません）。

```vb
Private Sub Worksheet_Change(ByVal Target As Range)
    On Error GoTo ExitHandler
    Application.EnableEvents = False

    新ファイル基準表_表示名からID自動補完 Target

ExitHandler:
    Application.EnableEvents = True
End Sub
```

### 動かないときの確認
1. 上記 `Worksheet_Change` が「新ファイル基準表」シートモジュールに存在するか
2. 標準モジュール `Module1` に `Public Sub 新ファイル基準表_表示名からID自動補完(ByVal Target As Range)` が存在するか
3. 即時ウィンドウで `Application.EnableEvents = True` を実行し、イベント無効化が残っていないか
4. `コード管理CSV` の構成が `A列=項目名 / B列=コード / C列=表示名` になっているか

## frmSealNew（動的UIの基盤と既存業務処理の接続）

既存のUserForm `frmSeal` を残したまま、コードで画面部品を生成する `frmSealNew` を使います。画面は810×600、ボタン／トグル23・入力欄14・ラベル19です。各ボタンの `WithEvents` イベントから既存処理へ向かう振り分けをソースで照合しています（変更後の各ボタンのクリック実機試験は未実施）。業務処理の実機検証はダミーブックに限定し、CSV・外部出力・旧ブック移行・印刷などは外部データ／環境が未確認なら実行しません。

### 含まれるテキストソース

- `clsFrmSealNewEvent_Code.txt`: 動的ボタン／トグルの `WithEvents` クラス
- `modFrmSealNewLayout_Code.txt`: 画面部品の生成と配置、起動マクロ `ShowFrmSealNew`
- `frmSealNew_FormCode.txt`: UserForm本体と既存ボタン処理のイベント振り分け
- `modSealShared_Code.txt`: シール見出し探索・単件転記・和暦／保存期間の共通処理。**標準モジュール名は `modSealShared`**。`frmSeal_` の旧実装と同じ処理をフォームなしで実行します。

### 検証用コピーへの導入

1. 対象ブックを閉じ、`.xlsm` とVBAProjectのバックアップを作ってから作業します。元ブックは変更しません。
2. `Module1` と `固定印刷設定` がなければ、それぞれ同名の標準モジュールとして導入します。**さらに `modSealShared_Code.txt` を `modSealShared` として導入**します。既に同名モジュールがある場合は上書き／重複追加せず、GitHub `main` と内容・依存関係を比較し、不足分だけを反映します。既存 `Module1` に今回の変更（旧フォームのヘルパー参照先を `modSealShared` に変更）が必要です。
3. `新ファイル基準表_SheetModule.bas` の内容は、標準モジュールではなくシート「新ファイル基準表」のコードモジュールへ追加します。既存 `Worksheet_Change`／`Worksheet_SelectionChange` があれば統合します。行移動クリック確定と自動補完に必要です。
4. `clsFrmSealNewEvent_Code.txt` をクラス `clsFrmSealNewEvent`、`modFrmSealNewLayout_Code.txt` を標準モジュール `modFrmSealNewLayout`、`frmSealNew_FormCode.txt` をUserForm `frmSealNew` へ導入します。部品の手配置は不要です。
5. `frmSeal` は削除・置換しません。`Module1` の旧フォーム**画面起動** (`frmSeal.Show`) は互換性のため残し、転記ヘルパーだけ `modSealShared` に振り替えています。デザイナーにトグルがない**検証コピーのみ**、`frmSeal_` の該当参照を `Me.Controls("tglDuplicateCheckMode")`／`Me.Controls("tglMoveMode")` の遅延参照にすると、コントロール未宣言によるコンパイルエラーを回避できます。職場の本来のフォームにはデザイナー差分の確認なしに適用しません。
6. **デバッグ > VBAProject のコンパイル**でエラーを解消してから `ShowFrmSealNew` を実行します。コンパイル未完のブックでは業務ボタンを有効化せず、更新処理はダミーデータのコピーだけでテストします。

### 自宅Excel向け起動ボタンと個別検証（2026-10-10）

元ブック・職場本番ブックは編集しません。`サンプルデータ/新ファイル基準表検証用.hermes-compile-stage-20261010.xlsm` から別途 `サンプルデータ/新ファイル基準表検証用.hermes-home-panel-20261010.xlsm` を作成しました。既存35コンポーネントと必要シート・参照を確認し、`Module1` と `modFrmSealNewLayout` の更新、`操作パネル` シート追加後に36コンポーネントのコピーでVBAProject全体をコンパイルしました（その場でコマンドの無効化まで確認）。再オープン時はコンパイルコマンドが有効表示に戻るため、毎回コンパイル済みと断定せず、必要時に再実行してください。空の旧 `frmSeal` はコンパイルを妨げなかったため削除せず、職場フォームにも触れていません。

- `modFrmSealNewLayout.InstallFrmSealNewLauncher` は、既存データシートに重ならない専用シート `操作パネル` を作成し、フォーム起動ボタン `btnOpenFrmSealNew` を1つ設置します。`OnAction` は現在の **ThisWorkbook の名前**で修飾して `ShowFrmSealNew` を呼びます。実機で起動先が戻ることと、再実行してもボタンが増えないことを確認しました。ブックを改名したときは `InstallFrmSealNewLauncher` をもう一度実行してリンクを更新します。マクロを有効化したブックで起動ボタンを使います。
- 既存の `Module1` にある手動計算モードへの切替・復元をヘルパーに集約しました。このPCでは `Application.Calculation = xlCalculationManual` が実際に1004で失敗します。最適化ができない場合は自動計算のまま処理を続け、元の計算モードへ戻す必要がある場合だけ復元を試みます。業務上の判定や出力形式は変えません。
- **CSV取込**：コンパイル段階ブックから作った使い捨てコピー上で、フォームの `CommandButton1` のイベントから実行。選択ダイアログだけ一時的にダミーCSVへ振り向け、ダイアログ表示を抑えた試験で、`目録CSV` の2件とログの成功を実際に読み取りました。一時VBA変更とダミー行は保存していません。通常のファイル選択ダイアログでの手動取込は別途確認が必要です。
